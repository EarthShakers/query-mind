# RAG 检索优化

## 内核

RAG 检索质量 = **索引质量** × **检索质量**。

**索引质量**（上游，决定天花板）：
| 维度 | 不足时 | 优化方向 |
|------|--------|----------|
| **解析** | 表格乱、公式错、信息丢失 | 多格式支持、智能模式、云解析回退 |
| **分块** | 块太大 → 噪音；块太小 → 碎片化；边界截断 | 多策略、Parent-Child、语义分块 |

**检索质量**（检索阶段）：
| 维度 | 不足时 | 优化方向 |
|------|--------|----------|
| **召回** | 漏答、答案不完整 | 多路召回、Query 扩展、Multi-Query |
| **精准** | 噪音多、答非所问 | BM25 混合、Rerank、Self-Query |
| **排序/去噪** | 相关文档排后面、上下文浪费 | 置信度路由、Rerank、去重、压缩 |

Pipeline 五阶段：**文档摄入**（解析+分块）→ **预检索** → **检索** → **后检索** → **生成**。每阶段解决不同问题。

RAG 应用评估见 [RAG_EVALUATION.md](RAG_EVALUATION.md)。

---

## 一、文档摄入：解析与分块

**目标**：把非结构化文档变成可检索的 chunk。

| 能力         | 状态 | 说明                                                            |
| ------------ | ---- | --------------------------------------------------------------- |
| 多格式解析   | ✅   | PDF/DOCX 本地 + LlamaParse 云，智能模式（本地优先、复杂回退云） |
| 多分块策略   | ✅   | standard / parentChild / semantic                               |
| Parent-Child | ✅   | 子块嵌入、父块返回，减少边界截断                                |
| 摘要索引     | ✅   | 可选嵌入摘要，高置信时直接 top-10                               |
| 分层索引     | ❌   | 文档级 + 段落级 + 句子级                                        |
| 增量更新     | ❌   | 文档变更时只重算受影响 chunk                                    |

---

## 二、预检索：Query 理解

**目标**：让 query 更饱满、更可检索，减少「问得不准」导致的漏召。

| 能力        | 状态 | 说明                                         |
| ----------- | ---- | -------------------------------------------- |
| Self-Query  | ✅   | 解析 query + filterTitle，「XX 文档里的 YY」 |
| filter 回退 | ✅   | filter 无结果时重试无 filter                 |
| Multi-Query | ✅   | 2–4 个 query 变体检索合并                    |
| Query 扩展  | ❌   | 多轮对话历史扩展 query                       |
| **Enrich**  | ❌   | 意图路由（是否检索）+ 结构化 filter 提取     |

**Enrich 形态**：① 意图路由式：判断是否依赖外部知识，不依赖则跳过检索；② 结构化：补全 query 并提取元数据 filter（如「那去年款的呢」→ Query + `{year: 2025}`）  
**痛点**：未提取到答案 / 答案不完整 → query 不够饱满；上下文与答案无关 → query 带历史噪音。

---

## 三、检索：召回

**目标**：从向量库中召回候选 chunk，兼顾语义与关键词。

| 能力            | 状态 | 说明                                |
| --------------- | ---- | ----------------------------------- |
| 向量检索        | ✅   | pgvector + DashScope 1024 维        |
| 空间隔离        | ✅   | 按 space_id 过滤                    |
| BM25 + 向量混合 | ❌   | tsvector + RRF 融合，提升关键词召回 |
| 多路召回        | ❌   | 向量 + 关键词 + 元数据              |

---

## 四、后检索：去噪与排序

**目标**：在候选 chunk 中做去重、重排、压缩，减少噪音、提升上下文质量。

| 能力              | 状态 | 说明                                            |
| ----------------- | ---- | ----------------------------------------------- |
| 置信度路由        | ✅   | score_gap/std 决定 top10 / rerank / multi-query |
| Rerank            | ✅   | Cohere rerank（可选）                           |
| Parent-Child 去重 | ✅   | 按父块去重，返回父块内容                        |
| 上下文压缩        | ❌   | 长 chunk 压缩后给主模型                         |

---

## 五、生成与评估

**目标**：生成答案 + 可追溯 + 闭环优化。

| 能力     | 状态 | 说明                                      |
| -------- | ---- | ----------------------------------------- |
| 工具调用 | ✅   | search_knowledge 返回                     |
| 引用溯源 | ❌   | chunk 高亮、可点击跳转                    |
| RAG 评估 | ✅   | 见 [RAG_EVALUATION.md](RAG_EVALUATION.md) |
| 用户反馈 | ❌   | 点赞/点踩、闭环，与评估数据关联           |

## RAG 进阶

> 以下为 Pipeline 之外的扩展方向。混合检索、Enrich、引用溯源等见前文各章及「六、下一步」。

| 方向                   | 说明                                                                 | 实现成本 | 收益                |
| ---------------------- | -------------------------------------------------------------------- | -------- | ------------------- |
| **Context Reordering** | 最相关 chunk 放 Prompt 最前和最后，规避 Lost-in-the-Middle           | 低       | 生成质量提升        |
| **Semantic Cache**     | 语义相似问题命中缓存，跳过向量库与主模型                             | 中       | 降本、提速          |
| **Visual Citation**    | 引用定位到 PDF 页坐标，弹出该页截图（依赖解析阶段记录 page_no/bbox） | 中       | 用户信任、体验      |
| **GraphRAG**           | 实体-关系图，Graph+Vector Hybrid，解决宏观总结类问题                 | 高       | 长文档/教材宏观问答 |
| **Agentic RAG**        | LLM 动态决策检索时机、优化 query，与 Enrich 有重叠                   | 高       | 检索决策智能化      |
